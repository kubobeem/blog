# WSL2 に 35B のローカル推論環境を足した

手元の GPU でそこそこ賢いモデルを回したくて、FreeToken の fork（atomicmilkshake 版）を WSL2 に入れた。

環境は RTX 4060 8GB、RAM 39GB、CUDA 13.1。既存の環境を壊さないように、別ディレクトリ・別 venv・別ポート（8080）で動かす。SHA は `cd0a6b5` で固定。

## モデル選びで詰まった話

35B の MoE を 8GB の VRAM に載せるので、量子化の選び方がすべて。最初に狙った `IQ3_XS` という型は **ggml に存在しない**。bartowski 版は名前だけ IQ3 で、実体が複数の型の混在だった。

この fork は「expert バンクは層をまたいで単一の型」という制約があるので、混在量子化はロード時に例外で落ちる。

そこで、GGUF のヘッダ先頭 32MB だけ range リクエストで取ってきて、tensor の型を実測するスクリプトを書いた。15GB を落としてから失敗するのは時間の無駄なので、ダウンロード前に判定できるようにした。

採用したのは `Ornith-1.5-35B-A3B`（15.51GB）。gate/up が IQ3_XXS × 40層、down が IQ3_S × 40層で、ちゃんと均一だった。

## 運用

`~/bin/ft-ornith` というラッパーを置いて、start / stop / status / log / version をまとめた。PID とログはファイルで持つ。

opencode 側は `opencode.jsonc` を触らなくて済んだ。既存の llamacpp プロバイダが 8080 を見ているので、`--served-model-name llama-cpp-128k` を合わせるだけ。

## 注意点

- この構成は fork の作者が検証した組み合わせではない。実績があるのは別の版
- `FREETOKEN_BIN_DIR` を PATH に通すと既存の `ft` コマンドと衝突する
- `pkill -f 'ft serve'` は他のプロセスを巻き込む。PID で殺す
- tq4 の KV キャッシュは MHA のときだけ効く
- 初回ロードに約 1 分かかる。もう1つの環境と同時起動はできない
