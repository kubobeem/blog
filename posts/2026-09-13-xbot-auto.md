# X の bot をタスクスケジューラで回し続けるようにした

前は手で叩いていた X の bot を、Windows のタスクスケジューラから `opencode run` を呼ぶ形で自動運用にした。30分おきに起きて、TL を見て、いいねと返信をして、たまに投稿する。

<!-- tags: X, 自動化 -->

## 構成

- twifork 2.4.0（`import twikit` のまま、`impersonate="chrome"`）
- Cookie は Playwright の `page.context().cookies()` から `auth_token` / `ct0` を抜いて `cookies.json` に保存
- `check.py` / `tl.py` / `act.py` / `engage.py` / `mentions.py` などの小さいスクリプト群
- Windows タスク `XBotAutoTweet`（Hidden）→ `auto.ps1` の無限ループ → `opencode run --auto --dir D:\code\twikit-bot`

## 結果

- 初回でいいね3・返信1・投稿1・RT1。すべて 226 / 403 なし
- 10本のバースト投稿（30秒間隔）が全部通過
- 交流バースト3回で計30件（いいね18・RT5・返信7）すべて ok
- 自動1回の RUN で、メンション9件への返信＋本人への返信＋いいね6＋RT2＋投稿2。合計21操作が全部 200
- 間隔は 90〜300分 → 5〜90分 → テスト1分 → 最終的に30分固定。深夜8時前は静観

## ハマったところ

- twikit の `login()` が廃止された（code 366）。ブラウザから Cookie を抜く方式に切り替えて、`login.py` は消した
- 新しいオンボーディングフローのパスワード送信が通らず、80回くらい連打した。原因を追うのをやめて `browser_login.py` を削除。SKILL.md に「このルートで行く」と実測だけ残した
- `auto.ps1` の認証切れ判定 `401|403` が、成功報告の「226/403なし」に誤マッチして止まる。`AUTH_ERR|Unauthorized|Forbidden` に限定した
- タスクが Ready に落ちたのは、Stop→Start で古いインスタンスが消えたせいだった。異常ではない

※ 自分のアカウントが30分おきに起きているのを見ると、少し怖くなる。
