# ファイル共有サービスを、公開できるところまで整えた

自分用に作っていたファイル共有サービス（Cloudflare Pages Functions + D1 + KV、ファイル実体は Telegram Bot）を、人に見せられる状態まで整備した。

やったことは、監査 → 仕様化 → 法的な整理 → 不要機能の削除 → R2 対応 → 管理画面 → デプロイ。

## 中身

- Functions の 14 エンドポイント + D1 + KV
- R2 は任意バインディング（`env.FILES`）として抽象化。未設定なら全件 Telegram に縮退する
- R2 側は 15MB の multipart、3日で自動削除、D1 の `SUM(size)` で 8GB 超えを弾く
- 管理画面と `/api/admin/*`（統計・報告一覧・強制削除・ストレージ切替）。IP は SHA-256 でハッシュ化

## 結果

- 本番 D1 に bundles 130 / files 114 / 1.91GB
- 期限切れが 72 バンドル 1.71GB、生存 10（17MB）、期限なし 37（185MB）
- クリーンアップを直したら滞留 88 バンドル / 1.78GB が解消、Telegram の使用量が 202MB → 105MB
- `super-file.pages.dev` にデプロイ成功。`file.kuboes.ninja` と `files.kuboes.ninja` のドメインも見つかった

## 途中で分かったこと

**法的な整理**は思ったより真面目にやった。電気通信事業法は「無料・広告なし」なら届出不要。著作権幇助は Winny 判決（最高裁 H23.12.19）の「相当の配慮」が基準になる。個人情報保護法・プロバイダ責任制限法・DMCA と合わせて spec にまとめた。

**R2 は使えなかった。** アカウントで未有効化で `code: 10042`。CLI からは有効化できず、カード登録が必要だった。結果として「R2 なし・自分専用の API」に方針転換して、公開サービスとしての運用はやめた。作ったものは残っているけど、公開はしない。

## ハマったところ

- `wrangler.toml` の `[triggers]`（Cron）は Pages では使えない。書いた瞬間に全 wrangler コマンドが壊れた。定期処理はリクエスト時の自発実行に変えた
- Windows の stdin パイプで libuv の assertion。secrets は REST API で設定した
- 日本語の文書に、無関係な韓国語や中国語が混ざる事故が5箇所。検査スクリプト（`check-doc-garble.ps1`）を書いて、誤検出 119 → 13 → 0 まで削った。ただしスペースを挟んだ誤語は機械では見つからない
