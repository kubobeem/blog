# ローカル LLM 環境を b11870 に総入れ替えして、速度の上限を測った

<!-- tags: LLM, ローカルLLM -->

`~/bin` の llama-server / llama-cli / llama-bench を b11870（v0.7.0 / commit 74bca3950）に入れ替えた。ついでに「なんか遅くなった」の原因を実測で切り分けた。

## 構成

- `llama-b11870-bin-win-cuda-12.4-x64`（53ファイル・611MB）を上書き
- 実機は RTX 4060 + 2080（16GB、8+8 で分割）+ RAM 48GB
- モデルは Ornith-1.5-9B の Q4_K_M と IQ4_XS
- 計測は `llama-bench`（ngl 99 / `-ctk` / `-ctv` / `-fa on` / `-ub`）と `llama-server`（200k ctx、q4_0 KV）

## 結果

更新直後は pp64 が 144.43 t/s、tg16 が 27.45 t/s（CUDA、ngl 99）。

コンテキスト別の tg はこうなった。

| ctx | tg (t/s) |
|---|---|
| 0 | 47.7 |
| 32k | 40.7 |
| 64k | 35.5 |
| 128k | 27.9（q4_0 KV）/ 27.2（q8_0 KV）|

つまり「40 t/s」は 32k まで。それ以上は素直に落ちる。

## 効かなかった設定

- **MTP を有効にすると prefill が 1969 → 142 t/s。** 14倍遅い。tg は 47.1 → 49.4 でほぼ変わらない。長いプロンプトでは切るのが正解
- **q4_0 KV は前回「速い」と書いたけど逆だった。** 生成速度はほぼ同じで、prefill が 2169 → 1124 と半減する
- `-ub 1024` と MTP は併用できない（`failed to create MTP context`）

## モデルの比較

同じベンチで、Ornith-1.5-9B が SWE-bench 70.6。Qwen3.5-9B が 53.2、gpt-oss-20b が 60.7。LFM2.5-8B-A1B は SWE 0.4 で、コーディングには使えない。

## ハマったところ

更新したのに CUDA バックエンドがロードされず、`--list-devices` が `(none)` を返していた。つまり CPU で動いていた。CUDA Toolkit は 13.3 しか入れていなかったので、12.4 用の cudart / cublas の DLL を bin に展開したら CUDA0: 4060 / CUDA1: 2080 が見えた。

「ベンチのパッチがあるはず」と言われて探したけど、そんなものは存在しなかった。パッチ、git diff、セッションDB、ホームを全文検索して時間を捨てた。`--spec-type` などは上流の仕様に無い。
