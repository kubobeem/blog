# YouTube の映像を ESP32 の画面に、音はブラウザで

<!-- tags: 電子工作, ESP32 -->

前の記事で作った MJPEG プレーヤー（PC が JPEG にしてシリアルで送るやつ）は 5fps しか出なかった。映画は無理だが、音楽を聴きながら小さい画面で映像が流れるくらいなら欲しい。というわけで、音だけブラウザに任せる構成にした。

## 仕組み

Web UI に YouTube の URL を貼ると、yt-dlp が落としてきた映像を ffmpeg で 320x240 の JPEG にし、シリアルで ESP32 に送る。音はブラウザで再生する。ブラウザの再生位置がずれたら、映像側がシークして追いつく。

制御は aiohttp のローカルサーバ（127.0.0.1:8765）+ WebSocket。ESP32 側はデコーダを TJpg_Decoder から JPEGDEC に差し替え、受信とデコードを別タスク・別バッファに分けた。

## 結果

5fps が 12fps になった。

| 項目 | 前 | 後 |
|---|---|---|
| 実効 fps | 5.0 | 12.0 |
| 1フレーム | 178ms | 約 63ms |
| デコード | 106ms | 約 25ms |
| フレームサイズ | 8.6KB | 6.5KB |
| ボーレート | 2Mbps | 3Mbps |

ドロップは 0 で、音とのずれは ±0.05 秒に収まっている。シークも 1 フレームで追従した（14.01 秒へ飛ぶとき `resync 11.70 -> 14.01` のログが1回だけ出た）。

フレームサイズが勝手に縮んだのは、7KB に収めるために画質を自動で下げるようにしたから。q=60 から 10 ずつ下げて、実測 25〜45 に落ち着いた。

## 分かったこと

- **80MHz はダメ。** fillScreen 18.7ms（約 65Mbps）まで出るのに、画面が砂嵐になる。たまに正常に戻るので厄介だった。確率的にビットが化けている。40MHz 固定が正解
- 描画の 38ms はほぼ SPI 待ち。`setMaxOutputSize(8)` で blit の回数を 300 回から 45 回に減らして少し稼いだ
- `--baud` を明示しても、こっちから PING を送らないと 1.5 秒後に 115200 に戻されて切れる。プロトコル側の都合

受信とデコードをパイプライン化したのが 8fps → 12fps の分岐点だった。同じシリアル速度でも、待ち時間を重ねるだけでこれだけ変わる。

※ 音をブラウザに逃がした時点で、たぶん負けている。
