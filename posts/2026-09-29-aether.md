# シェーダーパックを書いていて、コンパイルが通る嘘に負けた

<!-- tags: グラフィックス -->

Minecraft 用のシェーダーパックを書いている。1.21.1 + Iris + Sodium、RTX 4060 の 1080p 想定。遅延 G-buffer で、パスは gbuffers → deferred → composite → TAA → ブルーム → final。

## 通ったけど動かない

`build.py` が `#include` を解決して旧名を書き換え、`glslangValidator` で 24 個のトランスレーションユニットを検証する。ここは全部通る。

ところがコンパイルが通ったコードに、こんなバグが残っていた。

- `toGamma` と `toLinear` が同じ実装になっていた。逆変換していないので、色が二重に適用される
- `getJitterNdc()` でビューポートの除算が抜けていた
- `gl_FragCoord` を頂点シェーダ側でも参照していて、`FRAGMENT_SHADER` ガードが無かった
- もっともらしいけど嘘のコメントが残っていた（実装と合っていない説明）

コンパイラは構文しか見ない。意味が合っているかは見ない。当たり前なんだけど、24 ユニットが緑だと安心してしまう。

そこで、コンパイルでは捕まらない検査を4本追加した。上に挙げた4つは、その検査で見つかったもの。

## まだ動かせていない

実機でのレンダリングは未実施。Iris 1.7.3 / Sodium 0.5.11 の dev 環境で試したら、15 個の mod を並べたあと、ワールドを読み込む前に `Namespace (intermediary) does not match current runtime namespace (named)` で止まった。パック側の問題ではない（はず）。

なので、輝度表の数字（空と石で約 54:1、`BLOOM_THRESHOLD` 0.8）は全部計算値。実機で見ていない。

## 今の制限

- volumetric cloud なし
- 水の屈折なし
- フォグが球状（`fogShape = -1`、dimension uniform が無い）
- TAA はカメラの再投影だけなので、動く Entity が少しにじむ

ビルドと検査は通る。画面はまだ見ていない。
